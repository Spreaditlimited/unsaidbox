PRICE CHANGE CONTRACT
Saving catalogue prices does not change Stripe Prices, subscriptions, or
entitlements. Stripe amount changes require new Price objects. Before enabling
checkout, verify mode, currency, interval, amount, active status and product
against server-side configuration. Use a configuration revision to reject
stale checkout requests. Never trust a browser-submitted amount or Price ID.
Existing subscribers retain their original Stripe Price. Migrating them to a
new price requires a separate explicit workflow and customer communication.

SANDBOX SETUP AFTER INSTALLING THE FOUR TABLES
1. In the local project, run npm run billing:setup-sandbox. It uses ONLY the test
   key and creates/reuses a Pro product, four recurring Prices and a cancellation
   portal configuration. Rerun after changing catalogue prices in administration.
   It never changes existing subscriptions or deletes archived price mappings.
2. In your Mac terminal, use Stripe CLI to authenticate to the SAME sandbox as
   the saved key. Do not pass secret keys as command-line arguments.
3. Start snapshot forwarding:
   stripe listen --events checkout.session.completed,checkout.session.async_payment_succeeded,customer.subscription.created,customer.subscription.updated,customer.subscription.deleted,invoice.paid,invoice.payment_failed,invoice.payment_action_required --forward-to http://localhost:3001/api/billing/stripe/webhook
4. Save the listener's whsec_ value privately as UNSAID_STRIPE_TEST_WEBHOOK_SECRET
   in .env. Never paste it in chat. It differs from a Dashboard endpoint secret.
5. Set UNSAID_BILLING_MODE=test locally and restart the dev server. npm run dev
   supervises the local database tunnel; see docs/local-development.txt for the
   SSH-agent unlock requirement. Keep the Stripe listener running separately.
   Do not enable this in production.
6. Sign into a personal test account and visit /dashboard/billing. Use Stripe
   test cards only. Admin and personal-account authentication stay separate.
7. Verify successful payment, failed payment, duplicate submit/event, renewal,
   cancellation, stale pricing, cross-account access and outage recovery.
   Returned checkout URLs are not payment confirmation.

TAX AND LAUNCH
VAT settings are now available at /admin/billing: off by default, percentage
validated to two decimals, added on top (not inclusive). Stored in a separate
BillingConfiguration row with id "vat"; no additional migration is needed.
Saving settings is admin-only, CAPTCHA-protected, audited and revision-checked.
An explicit acknowledgement covers the single fixed rate applying to all new
checkouts; this is NOT jurisdiction/exemption detection or Stripe Tax automation.
At sandbox checkout the verified exclusive Stripe TaxRate is created/reused
automatically, then attached to the recurring line item. Restricted Stripe keys
need Tax Rates read/write permission. Provider failures block checkout.
Tax changes do not invalidate catalogue price mappings. Stale app pages must
reload. Returning through the app replaces outdated open sessions; a Stripe
checkout URL already open retains its previous settings until expiry. Existing
subscriptions are never silently repriced or retaxed by this setting.
Public pricing and the billing selector show the configured rate and full total.
